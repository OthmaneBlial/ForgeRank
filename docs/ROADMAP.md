# ForgeRank roadmap

This roadmap is ordered by evidence and user outcome, not artificial dates. “Implemented” means the behavior exists for legitimately available evidence; it never means that the local cohort is globally complete.

| Area                       | Current state                                                                                                                                                          | Next proof                                                                                                 |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Operational foundation     | Implemented locally: migrations, adapters, provenance, snapshots, scoring, rankings, queue/worker, budgets, health, and operator controls.                             | Accumulate a longer unattended run and exercise the complete Docker Compose stack.                         |
| Repository intelligence    | Implemented for available evidence: bounded Git analysis, score reasons, histories, timelines, technologies, structures, aliases, stale/error states, and exports.     | Broaden legitimately observed repositories and keep parser fixtures current as public documents change.    |
| Discovery and ecosystems   | Implemented for available evidence: eight explicit discovery modes, topics, collections, similarity, language/technology views, comparisons, and daily/weekly reports. | Accumulate natural 7/30/90-day baselines so more trend views become eligible.                              |
| Developer intelligence     | Implemented for confirmed profiles and explicit owned non-fork portfolios, including nine evidence-gated leaderboard modes and auditable corrections.                  | Expand confirmed profiles and author/account links without inference or contact-data harvesting.           |
| Product experience         | Implemented: responsive product routes, keyboard search, light/dark themes, PWA shell, dynamic social cards, guided synthetic demo, and evidence-first empty states.   | Complete real-device assistive-technology review and validate field performance on a public runtime.       |
| Distribution and community | Public project site, documentation, contribution guide, local verification contract, and registry-tested `forgerank` npm CLI are in place.                             | Select a reusable license, restore GitHub Actions after rework, and keep npm/GitHub releases synchronized. |

## Near-term priorities

1. Keep first-run value immediate through the isolated fictional demo while preserving a truthful empty real index.
2. Accumulate enough comparable observations to unlock meaningful longer-window momentum.
3. Prove the full deployment bundle with a clean Docker Compose run and an extended worker run.
4. Expand parser and failure fixtures without adding GitHub API, OAuth, token, hidden-endpoint, or external-AI dependencies.
5. Choose an explicit software license and restore the paused Actions workflow once the product rework stabilizes.
