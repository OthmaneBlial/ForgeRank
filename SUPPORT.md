# Support

ForgeRank is maintained in public, but it does not currently offer private product support or a guaranteed response time.

## Choose the right route

- **Unexpected behavior or a reproducible defect:** use the [bug report form](https://github.com/OthmaneBlial/ForgeRank/issues/new?template=bug_report.yml).
- **Incorrect source evidence, score, rank, or explanation:** use the [data or scoring challenge form](https://github.com/OthmaneBlial/ForgeRank/issues/new?template=data_or_scoring.yml).
- **A scoped product or documentation proposal:** use the [feature proposal form](https://github.com/OthmaneBlial/ForgeRank/issues/new?template=feature_request.yml).
- **A security vulnerability:** follow [SECURITY.md](SECURITY.md) and open a [private security advisory](https://github.com/OthmaneBlial/ForgeRank/security/advisories/new). Do not file it publicly.

Before opening an issue, search existing reports and read the [methodology](SCORING.md), [data-source boundary](DATA_SOURCES.md), and [current limitations](README.md#current-limitations). A missing value, bounded cohort, or stale-but-valid observation can be intentional.

Never paste credentials, tokens, private repository data, personal contact information, or unsanitized confidential logs into an issue. Small, reproducible examples and sanitized evidence are the fastest way to make a report actionable.
